# KFP integration

Qualify KFP SDK/backend 2.17.0 and the Dockflow IR profile specified by the
minimum `dockflow-pipelines` specification dependency. Apply its
[external publication contract](../053_dockflow-pipelines/006_artifacts.md#external-publication-through-parameters-and-importers).
The optional dockflow_artifacts.kfp module exposes importer_component, a public
factory accepting an artifact class, optional static JSON metadata, reimport
and optional graph component name. Call the factory outside the parent pipeline
definition; the returned graph component accepts a URI channel/string and returns
a typed artifact. It contains a standard importer in a nested graph, exposing
the URI as a parent input because native KFP 2.17 cannot resolve an upstream
task output directly in its importer. Dynamic metadata channels are outside
this initial portable contract. It produces normal KFP IR, without custom
executors, artifact subclasses, backend patches or a required service.

A wrapper publishes its local output through Publisher, then returns the URI
as a string parameter. The pipeline passes that value to the typed importer
and wires the resulting artifact to standard Input[Model]/Input[Dataset]
consumers. Preserve metadata and expose receipts/checksums through explicit
parameters or metadata as supported. Do not fake a computational artifact
producer: lineage includes the importer and parameter dependency.

For a custom-published output, do not also declare a conventional output artifact
for the same bytes. There is one durable published copy; runtime staging and
consumer downloads may still exist. Native Metrics outputs may remain ordinary
metadata artifacts. No mutation of KFP output URIs or fork of KFP is required.

Cache hits retain their original URI. A changed publication destination is an
input change where declared, and can prevent cache hits. Reuse across runs does
not copy bytes into a consuming run. Use immutable paths; readers must not rely
on the framework revalidating mutable external objects on every cache hit.
An explicit new destination is required for different bytes or metadata.

Directory/file data fetching remains the orchestrator's responsibility.
Credentials must be supplied through runtime mounts/secrets, never literal
secret environment values in public compiled YAML. Kubernetes-specific secret
bindings may be compiled into separate native deployment definitions.

For deterministic publication paths, pipeline wrappers pass pipeline_name,
exploration_id (default global), ordered step_number, computed step_digits and
component_version as real component parameters, alongside business inputs.
Different pipeline names prevent computational reuse across those contexts;
identical declared invocations within the same context can reuse the native
cache and retain their original URI. Hash input contents explicitly in the
component wrapper before execution, plus resolved parameters and component
version. Publication ID calculation does not replace KFP/Dockflow cache keys.
Neither backend must equate different registered artifacts solely because
contents match. Mutable external inputs still require appropriate versioning
or cache disabling; do not promise cache-time rehashing by native KFP.
