# Pipelines command interface

## Scope and invocation

This document defines the target first-release CLI. It consumes the shared
[CLI contract](../052_dockflow-cli/001_cli.md), including exit codes 0/1/2,
stdout/stderr, registration and side-effect-free help. These interfaces require
implementation and qualification; their specification is not test evidence.

All options below belong beneath `dockflow pipelines`. Bare `dockflow pipelines`
prints group help and exits 0. Group options precede the command:

```text
dockflow pipelines [--config PATH] [--endpoint URL | --local] [--json] COMMAND ...
```

`--config` overrides `DOCKFLOW_PIPELINES_CONFIG`; discovery and path resolution
follow [Configuration](003_configuration-and-backends.md). Endpoint precedence
is `--endpoint`, `DOCKFLOW_PIPELINES_ENDPOINT`, then an explicitly configured
`client.endpoint`. With all three absent, execute directly in this process's
execution context. Do not discover a server, launch Compose, or fall back to
direct execution after a connection error. An empty explicit endpoint is invalid.

An endpoint is an absolute HTTP(S) service base URL, optionally including a
reverse-proxy path prefix; append the API paths in [Service API](010_service-api.md).
Reject embedded credentials, query strings and fragments. Verify HTTPS by
default; use the configured CA bundle rather than an implicit insecure fallback.
Client token/CA settings follow Configuration and never become run parameters.

In direct mode, execution calls the same application core as the service without
starting HTTP. Docker remains required. A live owner of the state root makes a
competing direct mutation fail with an actionable operational error. Read-only
inspection may use a consistent persisted snapshot; never bypass the owner to
write its metadata. In service mode, the service governs storage, Docker and
state; local config is used only for client settings and explicitly loaded
compiled files. Client paths are not server paths.

Contention output identifies the resolved state root and available owner
instance UUID, execution-environment hostname, PID, local/service mode, project
ID, acquisition time and explicit endpoint. JSON output retains the structured
owner-conflict detail in [Service API](010_service-api.md); human output explains
that the caller may select the recorded service endpoint or wait for the direct
owner to finish. A recorded endpoint is a hint requiring explicit selection,
not automatic discovery or permission to retry elsewhere. Unknown/malformed
metadata still gives a busy diagnostic when the OS lock is held. An unavailable
locking mechanism or lock-file I/O failure is an operational failure distinct
from contention. No force-unlock, age expiry, PID-based takeover or lock-file
deletion command is part of this interface.

After a prior coordinator dies, a successful OS-lock acquisition is insufficient
for a new direct `run`: retained nonterminal/queued Runs or unresolved/
`reconciliation_required` Runs/attempts cause an operational refusal before
accepting the new Run. Explain how to explicitly start the service to reconcile
execution and drain the accepted queue. Never automatically rerun interrupted
work, assume its containers stopped, or start/connect to a service on the user's
behalf. Read-only inspection remains available under its existing contract.

`--help`, including nested command help, requires no configuration, state,
network, Docker or execution dependencies. CLI construction/import is lightweight.
There are no compile, build, push, deploy, Runnable or plugin-install commands.

## Run submission

```text
dockflow pipelines run NAME_OR_DEFINITION_ID_OR_PATH
  [--name TEXT] [--experiment EXPERIMENT_ID]
  [--parameter NAME=JSON]... [--input NAME=ARTIFACT_ID]...
  [--from TASK | --tasks TASK[,TASK...]]
  [--bind TASK.INPUT=ARTIFACT_ID]... [--use-execution TASK=ATTEMPT_ID]...
  [--scope global|keyed|run|none] [--scope-key KEY]
  [--wait | --no-wait] [--idempotency-key KEY]
  [--output none|trimmed|full] [--output-limit INTEGER]
  [--dockflow-output | --no-dockflow-output]
  [--component-output | --no-component-output]
```

Resolve a bare registered pipeline name against the selected local/server
catalog. A `definition_` public ID selects that immutable historical pipeline
snapshot explicitly, even if its registration is now unavailable. Treat an
absolute path, a path beginning `./` or `../`, or a `.yaml`,
`.yml` or `.json` operand as a compiled file in the client's filesystem. Configured
registration names cannot use those path forms. An uploaded display name that
matches a file-operand form is selected through its immutable definition ID or
KFP catalog lookup instead. Parse files as data; do not import
Python or compile them. In endpoint mode send the parsed compiled document,
its original UTF-8 source text, and not the client's filename. Preserve the
submitted compiled snapshot and its
identity according to [KFP compatibility](004_kfp-compatibility.md).

Validate the complete request before queue acceptance or task dispatch. Each
submission creates a fresh Run except a replay with the same idempotency key.
The default display name is the pipeline's registered/IR name, and the default
experiment is `Default`. Experiment arguments are public IDs, not ambiguous
display names. Parameter values are JSON: strings require JSON quotes, numbers
remain numbers, and booleans remain booleans. Reject duplicate assignments,
unknown names, type mismatches and parameters supplied as artifacts or vice versa.
For KFP numeric values, integers must lie within the exact portable range
`-(2^53-1)` through `2^53-1`; floating values must be finite. Apply the same
portable numeric rules to JSON metadata.

`--input` binds a supported root artifact input to a registered artifact. Where
the profile requires an importer, pass its declared URI parameter instead; do
not rewrite a parameter into a new graph input. `--bind` supplies an explicit
historical artifact to a selected task input. Task selectors use exact unique
slash-qualified compiled task paths from Execution; reject unknown, ambiguous
or duplicate selectors. `--from`
selects the named task and descendants; `--tasks` selects exactly the named
tasks. The options are mutually exclusive. Missing prerequisites, dependency-only
edges and historical attempt compatibility follow [Reuse](008_reuse-and-selection.md).
`--use-execution` selects a historical successful attempt's complete output set;
it is not permission to accept partial or incompatible outputs.

Scope defaults to configured `reuse.scope` (`global` absent an override).
For `keyed`, resolve the key from explicit `--scope-key`, then configured
`reuse.scope_key`; reject a missing/empty resolved key. Other scopes reject an
explicit `--scope-key` and do not inherit a configured key.
Scope changes never override a component's declared no-cache behavior or relax
integrity/equivalence requirements. These are opaque repository-local namespaces.

Direct execution is foreground and waits to completion; reject `--no-wait` and
`--idempotency-key` there. Service mode waits by default; `--no-wait` returns after
durable acceptance. Generate an idempotency key for a service submission if none
is supplied, reuse it during transport retries, and print it with the accepted
Run ID. If acceptance is uncertain, report that key; never silently submit again
with a fresh key. A wait connection failure does not cancel an accepted Run.

For a waited Run, return 0 only for `succeeded`; return 1 for failed, cancelled,
interrupted or unresolved outcomes. A successful `--no-wait` returns 0 for
acceptance, not completion. Always make the Run ID available once accepted.

## Inspection and management

The following grammar is complete for the initial interface. `ID` operands must
have the appropriate public type; names are accepted only where stated.

| Command | Behavior and options |
| --- | --- |
| `definitions list` | List registered pipelines and retained versions; `--name NAME` filters exactly. |
| `definitions show NAME_OR_DEFINITION_ID` | Show the current named pipeline or immutable snapshot, including digest and compatibility diagnostics. |
| `definitions validate NAME_OR_PATH` | Validate a registered pipeline or parsed compiled file without executing it. |
| `definitions refresh` | Reindex configuration-owned compiled definitions; preserve historical snapshots, mark missing configured registrations unavailable, and leave API-owned pipelines/defaults unchanged. |
| `components list` | List registered and indexed embedded component definitions; `--name NAME` filters exactly. |
| `components show COMPONENT_OR_DEFINITION_ID` | Show component identity, type declarations, compiled snapshot and referenced image. |
| `runs list` | List Runs; optional `--state STATE` and `--experiment EXPERIMENT_ID`. |
| `runs show RUN_ID` | Show the Run, resolved plan, task IDs, selected history, outputs and errors. |
| `runs cancel RUN_ID` | Request cancellation, including queued Runs; repeated cancellation is safe. |
| `tasks show TASK_ID` | Show task state, attempt IDs, input/output bindings, reuse decisions and producer links. |
| `artifacts list` | List artifacts; optional `--type TITLE` and `--availability STATUS` using the metadata availability enum. |
| `artifacts show ARTIFACT_ID` | Show type, revision, fingerprint, location, availability, provenance and pins. |
| `artifacts register --uri URI --type TITLE` | Register an external reference; validate and fingerprint its current contents. |
| `artifacts import --uri URI --type TITLE` | Import a managed immutable snapshot of existing contents. |
| `artifacts pin ARTIFACT_ID` / `artifacts unpin ARTIFACT_ID` | Idempotently add/remove the explicit retention pin. |
| `experiments create NAME [--description TEXT]` | Create a grouping with a project-unique display name. |
| `experiments list` / `experiments show EXPERIMENT_ID` | Inspect experiment groupings. |
| `logs RUN_ID [--task TASK_ID] [--attempt ATTEMPT_ID] [--follow]` | Read retained logs, optionally polling until terminal and drained. |
| `metadata check [--verify-contents]` | Read-only check of manifests, index consistency and availability; content hashing requires the explicit option. |
| `metadata rebuild [--apply]` | Default to a reconstruction plan; `--apply` performs the verified rebuild with exclusive maintenance access. |
| `clean [--apply]` | Default to a cleanup plan; explicitly apply only eligible contents under retention rules. |
| `capabilities` | Show the actual installation/server's qualified versions, profile, backends and limits. |
| `serve [--host HOST] [--port PORT]` | Explicitly start the service from explicitly selected configuration. |

List commands accept `--page-size INTEGER` (default 50, range 1–200) and
`--page-token TOKEN`. Return one page and its continuation token; do not silently
truncate or fetch unbounded history. Ordering and filters follow the native API.
No command deletes execution history or arbitrary unrecognized files.

Both external artifact commands additionally accept `--type-version VERSION`,
`--version LABEL`, and repeated `--metadata NAME=JSON`. For supported built-in KFP
types the schema version defaults to `0.0.1`; custom types require an explicit
schema version. Artifact data revision and KFP type schema version are distinct.
Metadata keys cannot use the reserved `dockflow` namespace. URIs and fingerprinting
follow [Artifacts](006_artifacts.md); an endpoint resolves `file://` on the server
within its configured allowed roots. The CLI does not upload a local file by
passing its path. No general binary-upload protocol is provided initially.
The KFP client's bounded pipeline/version upload methods separately register
compiled YAML/JSON. The native CLI needs no new upload command: its definitions
inspection and named/version-ID execution can use API-registered catalog entries
through the selected endpoint. This does not add artifact-byte or component-image
upload support.

`--local` explicitly selects direct mode despite endpoint environment/file
settings and is mutually exclusive with explicit `--endpoint`. An empty endpoint
does not substitute for `--local`. Service `serve` rejects explicit client
connection options and does not use `client.endpoint` to route execution.

`metadata rebuild --apply` and `clean --apply` require an idle execution owner,
revalidate the plan immediately before mutation, and fail on conflicting active
work. `--apply` is explicit user intent; do not add an interactive approval prompt.
Display the resolved project/state/store locations and protected/deleted counts.
The authoritative cleanup policies live in Artifacts and Metadata; a CLI flag
does not weaken them. Rebuild application is offline and direct-only: stop the
service, resolve uncertain execution, then rebuild with exclusive ownership.
An endpoint may return a rebuild plan, but `--apply` there is rejected with an
operational offline-required diagnostic. Other endpoint maintenance requests go
through the service owner.

`serve` rejects explicit `--endpoint` and implicit repository discovery. Ignore
client endpoint environment/file settings for this explicit startup command. Bind
`127.0.0.1:8080` by default; the container profile explicitly binds `0.0.0.0:8080`.
It holds the execution ownership lock until shutdown. It does not launch a Docker
daemon, database, registry or Compose. Missing runtime/service dependencies produce
an installation diagnostic; remote commands must not import them merely to run.

## Output, waiting and interruption

Human output uses concise tables/details with explicit states and IDs. Progress,
warnings and selected mode/project summaries go to stderr. Component logs do not
mix with structured command results. Group `--json` emits exactly one UTF-8 JSON
document with `schema_version: 1` plus `result`; list results contain `items` and
`next_page_token`. Failures in JSON mode emit `schema_version: 1` plus `error`
on stderr, using the native API error fields; successful stdout stays empty.
Never include credentials or tracebacks in ordinary errors.

`run --output` controls human result detail. Default `trimmed` displays Run
identity/state, submission key when present, output artifact IDs and scalar
outputs; omit the compiled definition and resolved plan from that summary.
`none` suppresses result detail but retains identity/state/key and error
diagnostics. `full` displays the complete accepted Run. `--output-limit` defaults
to 2000 characters per verbose block, minimum 128; mark shortening explicitly
and explain `--output full`. Apply this limit to trimmed KFP task-output summaries
and recognized executor-input JSON in local console logs. Never treat an
arbitrary component JSON message as generated executor metadata.

`run --dockflow-output/--no-dockflow-output` independently controls normal
orchestrator progress, KFP host task summaries/separators, recognized container-side
KFP INFO bookkeeping and the human Run result.
`run --component-output/--no-component-output` independently controls display of
local container stdout/stderr. Container-side KFP bookkeeping is displayed only
when both visibility switches are enabled.
Both default to enabled. Disabling component output hides stream labels and the
live-log heading as well; disabling Dockflow output alone keeps component stream
attribution and hides recognized KFP bookkeeping even with --output full.
Recognize the supported KFP executor's component lookup/loading, validated
executor-input JSON and output-file/no-output INFO messages by their specific
shapes. Do not suppress all messages sharing the KFP formatter: ordinary Python
component logging may inherit it. Unknown messages, container warnings/errors,
tracebacks and unvalidated metadata remain visible when component output is
enabled. With both enabled, the selected detail mode applies to recognized
metadata as above.
These are invocation-only presentation flags, not configuration, component
environment, submission parameters or logging-level changes.

With both disabled, successful human-mode runs produce no normal output.
Dockflow warnings, preflight errors, interruption/detachment diagnostics and
terminal failure identity/reason remain visible on stderr. Hidden component
stderr is still retained; failure does not implicitly replay suppressed logs.
Exit status is independent of display choices. Explicit group --json always
returns the complete machine result even when Dockflow human output is disabled.
Remote run applies the human-result switch, but continues to fetch no component
logs automatically; the component switch does not change separate logs commands.

Foreground direct execution forwards component stdout/stderr to stderr while
the container runs, after durable persistence, preserving stream attribution.
Normal newline-terminated messages appear as they arrive; a trailing partial
line is flushed at task completion. Buffering inside a component remains its
responsibility. Reassemble generated executor metadata across transport chunks
before applying display controls; bound incomplete presentation buffers to 1 MiB
and show unvalidated overflow unchanged. Preserve ANSI colors on a terminal,
strip color escapes when redirected or when NO_COLOR is present, and never
modify retained log text for presentation.
Ordinary component messages remain visible in every output-detail mode unless
component output is explicitly disabled. Terminal
disconnection must not turn completed work into a failed attempt. Display modes
never change persisted records, log text, artifact bytes, execution/reuse identity
or API contracts. Group `--json` always retains the full machine result;
display options affect only terminal diagnostics in that mode. Remote `run`
uses these final-result modes, with logs inspected through `logs` separately.

JSON log output returns one bounded page (`entries`, `next_cursor`, `terminal`);
add `--cursor TOKEN` and `--limit-bytes INTEGER` (default/max 65536). Reject
`--json` with `--follow`; human follow polls the same bounded endpoint and handles
rotation through retained sequence cursors. A task/attempt filter must belong to
the specified Run. Logs preserve stream and attempt attribution; they are not a
binary artifact download mechanism.

Ctrl+C in direct execution requests interruption, stops dispatch, terminates owned
task containers, and retains logs/manifests. Return 1 when interrupted; an abrupt
crash requires reconciliation, not a fabricated terminal state. Ctrl+C while
waiting for a service Run only detaches the client and returns 1 with the Run ID.
Use `runs cancel` to stop accepted service work. Service signal handling follows
[Execution](005_execution-and-lifecycle.md), including shutdown reconciliation.

Verify offline help, JSON purity, foreground/service parity, lock conflicts,
typed argument rejection, idempotent transport recovery, partial selection,
cancellation and publication failure before advertising this interface.
